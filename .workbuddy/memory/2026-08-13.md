## 浮窗最小化后无法拖动（content.js）
- 根因：拖拽 `mousedown` 只绑定在 `header` 上；浮窗收起(collapsed)时 CSS 把 `header` 设为 `display:none`，只剩 `collapsed-body` 可见且无拖拽监听，导致收起后整条无法拖动。
- 修复（`extension/content/content.js`）：
  1. 把拖拽 `startDrag` 同时绑定到 `collapsed-body`（收起态唯一可见元素）。
  2. 用 `dragJustHappened` + 位移阈值(>4px) 区分"拖动"与"单击展开"，避免拖动后误触展开。
  3. `collapsed-body` 光标由 `pointer` 改为 `move`。
- 注意：content script 改动需在 `chrome://extensions` 重新加载扩展才生效。

## 会话明细：滚动到底自动加载更多，最多一个月
- 位置：`extension/popup/popup.js` 的 `renderSessions`（会话级明细列表，原本 `slice(0,30)` 一次性渲染，无滚动加载、无时间限制）。
- 实现：
  1. 用 `lastActive` 过滤最近 30 天内的会话（`SESSION_MONTH_DAYS=30`），超出一个月的不渲染。
  2. 分页渲染（`SESSION_PAGE=30`）：首批渲染后，用 `IntersectionObserver` 监听列表底部哨兵 `#sessionSentinel`（root=null 监听 popup body 视口，rootMargin 120px 提前触发）；进入视口则 `requestAnimationFrame` 追加下一批。
  3. 全部加载完哨兵显示「已加载最近一个月全部会话明细」并 disconnect；hint 显示「近一个月 N 个会话（全部 M 个）」。
- 注意：popup 滚动容器是 `body`（overflow-y:auto），列表不在独立滚动容器，故用默认 root；隐藏 tab-panel 内元素不可见时 observer 不触发，切到「会话」tab 后才触发，符合预期。
- 配套 CSS：`.sess-sentinel` / `.sess-sentinel.done` 加到 `popup.css`。

## popup 定时闪一下 + 分页/状态被重置（renderSummary 全量重渲染）
- 根因：`popup.js:1138` `setInterval(renderSummary, 5000)`，每 5 秒把整个 popup UI 全量重渲染一遍（含会话明细、图表、最近记录、预测、对比、预警）。
  - 会话明细的 `_sessData/_sessRendered` 被清零、`sessionList` innerHTML 重建 → 已滚动加载的分页被清空（最明显症状，由上面的分页功能暴露）。
  - 列表/图表重建也会导致闪烁、滚动位置/展开状态丢失。
- 修复：给 `renderSessions(bySession, opts={})` 加 `preserve` 模式。定时刷新时传 `{preserve:true}`（renderSummary line 98 已改）；preserve 且已渲染过分页时，只同步 `_sessData/_sessMaxTotal`、更新 hint 与底部 sentinel 状态，**不重建 DOM、不清零分页**，消除会话明细的清空/闪烁。
- 后续：`renderSessions` 的 preserve 只解决了会话明细。图表/最近记录/预测/对比/预警等仍每 5 秒被 innerHTML 重建 → 闪烁 + 这些区域的状态（如记录详情展开、会话滚动）被重置。

## popup 增量渲染守卫（彻底消除闪烁与状态重置）
- 新增 helper `renderChanged(key, data)`（`popup.js` ~line 134）：用 `JSON.stringify` 算数据签名，`_renderSigs` 缓存上次签名；签名未变则跳过该 render 函数的 DOM 重建。`popup.js` 每次打开是全新文档，`_renderSigs` 初始为空，首次渲染必执行。
- 给 renderSummary 调的所有 innerHTML 重建函数加守卫：
  - `renderChart('chart', trend)`
  - `renderCacheStats('cacheStats', [cacheStats, buckets])`
  - `renderCacheByModel('cacheByModel', byModel)`
  - `renderModelCompare('modelCompare', {m: byModel, v: modelMetric})` —— 含 `modelMetric`，切 Token/成本视图时签名变化会正确重渲染（来回切换不会误跳过，因存储签名=上次实际渲染态）
  - `renderPrediction('prediction', pred)`
  - `renderAlert('alert', alertResult)`
  - `renderComparison('comparison', comp)`
  - `renderRecords('records', records)` —— 守卫后「记录详情展开」状态在定时刷新时不再被收回
- `renderSessions` 仍走自身 preserve 逻辑（增量加载分页），不重复加守卫。
- 效果：数据无变化时 5 秒定时器几乎零 DOM 操作，整页不再「闪一下」，展开/滚动/分页/视图状态全部保留；有新数据时对应区域仍会刷新。已 `node --check` 通过。

## 修复后引入的回归（用户反馈「数据都没了」）
- 根因：`db.js` `getSummary` 把 `const records = await getRecordsSince(now - SUMMARY_WINDOW_DAYS * dayMs)` 写在 `const now`/`const dayMs` 声明**之前**。`const` 有暂时性死区（TDZ），运行时在 192 行引用未初始化的 `now` 抛 `ReferenceError: Cannot access 'now' before initialization` → `getSummary()` 崩溃 → popup 整页空（IndexedDB 数据未丢，只是读不出）。
- 坑：`node --check` 只查语法不查 TDZ，所以上一轮「6 文件全过」漏掉了这个运行时错误。
- 修复：把 `const now = Date.now(); const dayMs = 24*60*60*1000;` 移到 `getRecordsSince(...)` 之前（db.js:190-194）。重新 `node --check` 6 文件全 OK。
- 教训：改动涉及「把原本不引用某变量的行，换成引用该变量的行」时，必须确认被引用变量已在作用域内先声明；`node --check` 不足以证明运行时正确，需人工读作用域或跑单测。
- 注：修复后 summary 范围仍为近 30 天（SUMMARY_WINDOW_DAYS），超 30 天的数据不进汇总/会话明细视图，但仍在 IndexedDB 中（属预期性能取舍，非丢失）。
- 用户侧：需在 `chrome://extensions` 重新加载扩展才会生效。

## 月份边界修正（用户问「一个月最多31天，取30天合适？」）
- 问题：`SUMMARY_WINDOW_DAYS=30` 取数窗口 + `month` 桶用 `now-30*dayMs`（滚动窗口），在 31 天月份月尾会砍掉当月最早 1 天，且「本月」实为「最近30天滚动」语义不对。
- 修复：
  1. `db.js` 新增 `startOfMonth(ts)` helper（仿 `startOfDay`，setDate(1) 归零）。
  2. `SUMMARY_WINDOW_DAYS` 30→31，取数窗口拉满最长月份仍有余量（同时保证 14 天趋势数据完整）。
  3. `getSummary` 的 `month` 桶 `since` 由 `now-30*dayMs` 改为 `startOfMonth(now)`，即真正的自然月。
  4. `popup.js` `SESSION_MONTH_DAYS` 30→31（会话明细「近一个月」同样避免月初 1 天截断）。
- 校验：db.js / popup.js `node --check` 通过。注意 `all` 桶仍为「近 31 天」聚合（原 2000 条上限的延续近似，非真正全量）。
